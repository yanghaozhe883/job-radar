## 1. 产品定位

**一句话**：帮求职者把一个「找得到机会」的痛点，变成一个"机会主动找上门"的体验 —— 用「雷达」监控 + 「智能」匹配 + 「炫技级」UI，在茫茫 JD 里照亮属于你的那一个。

**产品名**：求职雷达（Job Radar）
**Slogan**：*点亮雷达，让好机会主动找到你。*

**与竞品的差异化**（BOSS直聘 / 拉勾 / 脉脉 / 智联）：
- 竞品强在"海量职位库 + 聊天直聊"。
- 我们强在 **「实时雷达」**：不是被动刷列表，而是**持续监控目标维度**，有新职位**主动推送**，并给出**为什么匹配你**的可解释理由。
- 用 **顶级 UI/UX（炫技）** 建立"高级感 + 愉悦感"，形成记忆点，而非功能堆料。

### 核心价值主张（Value Proposition）
1. **省时间**：雷达帮盯，不用手动反复刷。
2. **不错过**：新职位/抢手的岗，第一时间推给你。
3. **匹配准**：基于偏好 + 可解释打分，告诉你"这个岗位为什么适合你"。

## 2. 目标用户与场景

| 维度 | 说明 |
|------|------|
| 主用户 | 一线/新一线城市的**社招 & 准应届**求职者（22–35 岁），至少 1 段求职经历 |
| 场景 A（主动） | 有明确目标：设定"岗位/城市/薪资/公司"，雷达持续盯，榜单+推送 |
| 场景 B（探索） | 想换行/看机会：雷达输出"机会热力图/趋势"，帮发现新方向 |
| 场景 C（被动/即时） | 看见心仪 JD 想投：一键直达收藏/投递，甚至自动生成打招呼语 |

**不做的**（MVP 阶段）：
- 不做企业端/HR 端（定位纯求职者侧）。
- 不做社交/社区。
- 不做付费求职培训/课程。

## 4. 信息架构 / 页面结构

底部导航 **4 Tab**（移动端黄金结构）：

```
┌─────────────────────────────┐
│  Tab1   Tab2   Tab3   Tab4   │
│  雷达   机会   收藏   我的     │
└─────────────────────────────┘
```

- **Tab1 雷达**（产品心脏）：雷达可视化主界面（扫描/波纹动效），显示"正在盯 X 类职位"，新机会卡片从雷达中"照出"。
- **Tab2 机会**：职位流（卡片列表）+ 搜索 + 筛选。
- **Tab3 收藏**：收藏/投递记录 + 状态流转。
- **Tab4 我的**：偏好设置、简历、通知、关于。

**二级页**：职位详情、雷达配置、筛选器、登录/注册、设置。

**炫技重点页**：`雷达页`（动态扫描/雷达波纹/粒子）、`职位详情`（共享元素转场、JD 渐入、技能匹配可视化、毛玻璃头图）、`机会流`（卡片横向3D切换、滑动动画）。详见 §7。

## 5. 核心数据模型（后端先行）

> 以 PostgreSQL 为基准，字段为最终开发骨架。

```
users          用户(id, openid, 手机号, 昵称, 头像, 城市, 目标岗位tags[], 地区tags[], 薪资min/max, 偏好权重json, 创建时间)
resumes        简历(id, user_id, 姓名, 期望岗位, 技能tags[], 履历json, 附件url, 更新时间)
companies      公司(id, 名称, 规模, 行业, 城市, logo, 简介, 融资阶段, 网站)
jobs           职位(id, company_id, 标题, 城市, 薪资min/max, 类型, 经验, 学历, 技能tags[], 描述, 数据来源, 抓取时间, 是否在职)
job_snapshots  职位快照/job_id(用于"已投过的岗位降价"类提醒)
user_jobs      用户-职位交互(id, user_id, job_id, 状态[seen/favorite/applied/hidden], 打分, 匹配理由json, 时间)
alerts         雷达订阅(id, user_id, 条件json, 是否启用, 创建时间)
push_log       推送记录(id, user_id, job_id, 类型, 内容, 时间)
match_reasons  匹配理由(id, job_id, user_id, 维度json, 权重)
```

关键关系：`users 1—N resumes / alerts / user_jobs`；`jobs N—1 companies`；`user_jobs` 为用户跟岗位的多对多交互。

## 6. 智能匹配方案

**两层召回 + 一层解释**：
1. **规则过滤**：城市/薪资/类型/经验硬筛，砍掉明显不匹配。
2. **向量召回**：JD 文本 + 用户偏好（技能、岗位）embedding 计算语义相似度（后端维，见 §8）。
3. **打分 + 解释**：按 `薪资匹配度 × 技能重叠 × 公司吸引力 × 距离/时效` 加权得总分；把**各维度贡献写到 `match_reasons`**，前端展示"为什么推荐你"。

> MVP 可先用**规则 + 关键词权重**跑通（无需模型），V2 再切向量检索，不影响前端。

## 7. 设计语言与炫技方向（前端重点）

### 7.1 设计观
- **基调**：深邃科技感 + 高质感玻璃拟态（glassmorphism）+ 克制的霓虹辉光。深色为主，浅色为辅。
- **气质关键词**：雷达、扫描、光、精准、可靠、未来感。
- **一句话**：让用户觉得"这不是找工作工具，是一部科幻操作台"。

### 7.2 色彩系统（Design Token 基准，可调）
```
--bg-primary        #0A0E17   (深空黑蓝)
--surface           #151B29   (面板)
--surface-glass     rgba(255,255,255,0.06) (磨砂玻璃)
--primary           #2DE1C2   (雷达绿 / 信号绿)
--accent            #6C7CFF   (辉光蓝)
--success           #22D07E
--warning           #FFB020
--danger            #FF5A6A
--text-primary      #FFFFFF
--text-secondary    #8A94A6
--border            rgba(255,255,255,0.08)
```

### 7.3 动效/炫技清单（按页）
| 页面 | 炫技点 | 技术 |
|------|--------|------|
| **雷达页** | 雷达扫描波纹、粒子轨迹、新机会从雷达"照出"弹出 | Compose Canvas + Canvas 动画 + 粒子系统 |
| **机会流** | 卡片 3D 滑动、滑动擦除、横向翻转、弹簧回弹 | `graphicsLayer` 变换 + `AnimatedContent` + 弹簧动画 |
| **职位详情** | 顶部毛玻璃头图、JD 逐段渐入、技能匹配可视化（如技能雷达图/进度环） | `RenderEffect` 模糊 + Canvas 绘制 + 共享元素转场 |
| **全局** | 深色一致、触觉反馈、沉浸式、状态切换平滑过渡 | `VibrationEffect` + 主题 Token |

> ⚠️ 原则：**每个动效必须有用途**（引导/反馈/愉悦），禁止纯堆料带来的卡顿和过度设计。性能预算：主帧 <16ms，雷达页专用优化。

### 7.4 设计流程
先出**设计 Token + 高保真稿**（设计语言定稿）→ 再 Android 打样验证动效 → 定稿后镜像 iOS。

## 8. 技术架构（承接上轮选型，已确认）

### 8.1 Android（优先端，确定）
- Kotlin + **Jetpack Compose**，**MVI + Clean Architecture**，**Hilt** 依赖注入。
- **Retrofit**（网络）+ **Room**（本地）+ **Coil**（图片）+ **StateFlow**（状态）。
- 实时：后端 **WebSocket**（雷达实时）+ **FCM**（后台推送）。
- `SharedTransitionLayout` (Compose 1.7+) + `AnimatedContent` + `RenderEffect` + `Canvas`。

### 8.2 后端（确定）
- **Kotlin + Spring Boot**（默认；若你选 Go 换）。
- **PostgreSQL** 主库；**Redis** 缓存/热职位/限流。
- 数据采集：**job 聚合源**（见 §9 合规）；`WebSocket` 对 Android 客户端实时推送。
- REST API + 统一响应契约 `{ code, message, data }`，前端 mock 阶段即对齐该契约。

### 8.3 iOS（后续镜像，本次不展开）
Swift + SwiftUI，架构/契约与 Android 对齐，炫技以 `matchedGeometryEffect` 等实现。

## 9. 数据来源与合规（⚠️ 优先级最高，须先确认）

这是本方向里**唯一的重大风险项**，直接决定后端能否落地，务必先拍板。

**可选策略（按合规/风险从高到低排序）：**
| 策略 | 说明 | 风险 |
|------|------|------|
| a. 官方开放平台/授权 | 接入平台官方开放接口（BOSS 直聘开放平台等，部分需资质/付费） | 低，最合规 |
| b. 招聘联盟 / 雇主直投 | 与企业合作获取 JD（可做成"内容聚合"而不含个人数据） | 低中 |
| c. **爬虫聚合** | 抓取公开职位页（拉勾/BOSS/脉脉/智联） | **高**（反爬、robots、肖像权、数据来源合法性；有法律风险） |
| d. AI 生成/模拟数据 | 用于 MVP 演示、效果验证，不涉真实数据 | 极低 |

**`[已确认]` 数据来源策略：c —— 直接用爬虫抓取公开职位数据（BOSS 直聘 / 拉勾 / 脉脉 / 智联等）。**

> ⚠️ 这是产品负责人已拍板的决定。作为工程基线我按此推进，但**合规风险是主任性的**，请在正式上架前完成法定审查。下节为必须遵守的红线。

### 9.1 爬虫合规红线与规避（必须遵守）

1. **只抓公开页面，不碰登录态 / 用户数据 / 个人隐私字段**。不采集任何真实的求职者个人信息、简历、联系方式。全链路禁止身份证、生物识别等敏感数据。
2. **尊重 `robots.txt` 与平台服务条款**。对标注 `Disallow` 的路径不抓；上架前**书面评估**平台条款与著作权/不正当竞争风险。
3. **限流与频率控制**：单域名并发 ≤ 2，随机间隔（如 3–8s），避免对目标造成压力；做失败退避、IP 池可控（但遵法）。
4. **U-A 标识与留痕**：设置明确 User-Agent 表明是合规采集程序；记录抓取日志 / 数据出处（`jobs.data_source` 字段），保证可追溯与可下架。
5. **只存必要字段**：抓取的 JD 截断/去重，避免整库复制；标注数据来源与抓取时间。
6. **默认测试环境：法律风险自担**。第三方平台的职位数据版权与使用许可不归我方，**商业化运营前须律师出具意见**；若下游被诉，风险由产品侧承担。

> 若后续法务判定某项不可行，**回退路径**为：模拟数据（MVP 不受影响）→ 官方/联盟渠道（§9 的 a/b）。切换不影响前端与接口契约。
